## 初期モデルと担当外の修正

`defaultModel` は記録内モデルIDまたはnull。`defaultModelName` は元の一覧の選択名、`defaultModelSources` は一覧とモデルの出典URL。188版は保存された公開日と当該版の一覧が一致。97版はnullと `defaultModelVerification: "unverified"`。これは再現画面用の候補であり、製品が当時実際に既定にしたモデルを断定しない。ChatGPT 2022-11/12も、対応する初期GPT-3.5の記録が一致しないためnull。後発のGPT-4で補わない。

**画面側は未修正。** `web/js/app.js` の初期状態は `models.find(modelFits)` が見つからないと `gpt-4-0314` へ進む。版切替も一致がなければ前のモデルを維持する。`defaultModel` を読んでおらず、nullも尊重しない。レビュー担当は同ファイルで初期状態と `selectTool` を接続し、候補が不明なら未確認として表示する必要がある。ユーザー指定の固定モデルは別扱いで維持すること。担当外のため本作業では変更していない。よってChatGPT 2022-11の実画面でGPT-4が選ばれないことは**未達成**。

**ビルド側も担当外。** `scripts/build-web.js` のharness読み込みは `v.available` を捨て、設計・調査資料の一覧または空配列で上書きする。追加版や、従来コード内で追加されていたツールを入力へ集約すると一覧を失う。そのため下記の実行では、通常のオフラインビルド後に担当内の `web/data/catalog.json` へ入力のモデル欄を同期した。レビュー担当は同スクリプトで入力の `available` と初期モデルを優先するよう修正すること。通常コマンドだけでの再構築はこの同期を含まない。

仕様と既存カタログの公開月が食い違う既存版（Aider初期、Codex CLI後期、Cline後期など）は `spec.from` に仕様値を保持するが、既存の生成処理が外部の版データで `from` を上書きする。初期モデルの照合は実際に生成された `from` で行った。公開月の一括修正は未実施。

## 実行と結果

`npm run build:web -- --offline` をNodeラッパーから実行。Nodeの一時読み込み設定で書込先を `web/data/` に制限し、ネット接続を禁止。`MODEL_MEMENTO_HOME` は存在しないプロジェクト内パスを指定し、個人の保存データ・設定を読まない構成。実行中に `web/lib/core.js` と `web/.nojekyll` の担当外書き込みを省略。HTMLへの書き込みも省略する設定だが、今回の実行では必要がなかった。インストール、コミット、push、サーバー、アプリ、別agentの起動なし。

最初の `node --input-type=module` による4件の検査は終了番号1、`tests 4 / pass 1 / fail 3`。モデル一覧が消える実問題を発見し、入力の一覧と生成物を同期。残る2件はClineの独立一覧画面にも会話を要求した検査側の前提が誤っていたため修正。2回目は終了番号1、`tests 4 / pass 2 / fail 2`。検査用の要素ツリーにCursorが使う `after` がなかったため補った。3回目は終了番号1、`tests 4 / pass 3 / fail 1`。Playground 2020-08は共通の編集可能な文章欄から送信するため、form内のtextareaを前提にした検査を修正。描画担当のコードは変更していない。4回目の最終実出力は下記。

確認はNode内の要素ツリーとイベントで行う。ブラウザーを開いた確認、CSSの実寸・見た目、狭い画面、実サービス接続、当時の応答再現はunverified。通常の `npm run check:web` はサーバー等を起動するため未実行。`web/data/f1-audit.json` に44件のID・出典・構築出力・初期候補件数・初回の失敗を保存。
