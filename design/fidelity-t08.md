# T08 — Roo Code webview

The catalog describes all five snapshots as `vscode-panel`. The February item is a CLI release tag, but the renderer uses the extension webview **at that tag**, not the CLI. This is a choice to honor the catalog surface; it is not a claim that the CLI has this interface. The [February CLI release](https://github.com/RooCodeInc/Roo-Code/releases/tag/cli-v0.1.6) is dated February 27, 2026. The other release dates are verified on the [3.9.2](https://github.com/RooCodeInc/Roo-Code/releases/tag/v3.9.2), [3.51.1](https://github.com/RooCodeInc/Roo-Code/releases/tag/v3.51.1) and [3.53.0](https://github.com/RooCodeInc/Roo-Code/releases/tag/v3.53.0) release pages. The final item uses the exact catalog commit. A search across *all* commits on each date to establish the mathematically closest revision was not possible: GitHub's unauthenticated tree API returned 403. The catalog's same-day tags and exact recorded commit are used; their status as the closest commits is unverified.

## Source and interpretation

- [2025 ChatView](https://github.com/RooCodeInc/Roo-Code/blob/v3.9.2/webview-ui/src/components/chat/ChatView.tsx), [composer](https://github.com/RooCodeInc/Roo-Code/blob/v3.9.2/webview-ui/src/components/chat/ChatTextArea.tsx), [English strings](https://github.com/RooCodeInc/Roo-Code/blob/v3.9.2/webview-ui/src/i18n/locales/en/chat.json), and [auto-approval menu](https://github.com/RooCodeInc/Roo-Code/blob/v3.9.2/webview-ui/src/components/chat/AutoApproveMenu.tsx) place the greeting and optional history above a separate auto-approval row, followed by the composer. Greeting padding is 20px horizontally; composer padding is 8px and radius 2px. The selector chooses a saved API configuration, not a raw model.
- [February ChatView](https://github.com/RooCodeInc/Roo-Code/blob/cli-v0.1.6/webview-ui/src/components/chat/ChatView.tsx), [composer](https://github.com/RooCodeInc/Roo-Code/blob/cli-v0.1.6/webview-ui/src/components/chat/ChatTextArea.tsx), [tips](https://github.com/RooCodeInc/Roo-Code/blob/cli-v0.1.6/webview-ui/src/components/welcome/RooTips.tsx), and [English strings](https://github.com/RooCodeInc/Roo-Code/blob/cli-v0.1.6/webview-ui/src/i18n/locales/en/chat.json) show a vertically centered home region with tips and a lower input, followed by mode, API configuration and auto-approval selectors. History only appears when there are prior tasks. The hero's product artwork and all source icons are omitted. Labels replace icon-only actions, and two short tip titles replace the longer body copy.
- [March ChatView](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/components/chat/ChatView.tsx), [composer](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/components/chat/ChatTextArea.tsx), and [tips](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/components/welcome/RooTips.tsx) were fetched and their SHA-256 hashes match the corresponding February files. Their screens intentionally match.
- [April ChatView](https://github.com/RooCodeInc/Roo-Code/blob/v3.53.0/webview-ui/src/components/chat/ChatView.tsx) changed, but its examined home region still contains the same hero, tips and conditional history; the [composer](https://github.com/RooCodeInc/Roo-Code/blob/v3.53.0/webview-ui/src/components/chat/ChatTextArea.tsx) and [tips](https://github.com/RooCodeInc/Roo-Code/blob/v3.53.0/webview-ui/src/components/welcome/RooTips.tsx) match March by SHA-256. No unsupported visible change is invented.
- The [record ChatView](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/webview-ui/src/components/chat/ChatView.tsx) also permits an optional [worktree selector](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/webview-ui/src/components/chat/WorktreeSelector.tsx), whose [English labels](https://github.com/RooCodeInc/Roo-Code/blob/b867ec9145750d0ae1ff7f02d35406e9bf2a0b16/webview-ui/src/i18n/locales/en/worktrees.json) include Worktree and No branch. This exhibit displays that optional state. The same conditional selector also exists in the other 2026 snapshots; this is not asserted to be a new feature of the record.
- Mode names come from [2025 definitions](https://github.com/RooCodeInc/Roo-Code/blob/v3.9.2/src/shared/modes.ts) and [2026 definitions](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/packages/types/src/mode.ts). Product pictograms are deliberately omitted. The selector displays a subset and is a visual example; it does not alter the museum's generation mode.
- The [2026 profile selector](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/components/chat/ApiConfigSelector.tsx) chooses a saved configuration and opens settings; the [settings model picker](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/components/settings/ModelPicker.tsx) changes the model in a profile. The available models and actual selected profile are account-dependent and remain unverified; no model options are invented. Museum integration supplies a separate sourced slot beside the profile control. The profile, auto-approval, attachment and prompt-enhancement controls lead to museum views; they do not carry out the original extension operations.
- Roo maps its [CSS](https://github.com/RooCodeInc/Roo-Code/blob/v3.51.1/webview-ui/src/index.css) to VS Code theme variables. The reconstruction uses values from the current [Dark Modern theme](https://github.com/microsoft/vscode/blob/main/extensions/theme-defaults/themes/dark_modern.json): sidebar `#181818`, editor `#1f1f1f`, input `#313131`, foreground `#cccccc`, muted `#9d9d9d`, focus `#0078d4` and border `#2b2b2b`. This is an example host theme, not a verified historical default or a Roo-owned palette. The example editor text, proportions, outer width, responsive breakpoint and some spacing are reconstruction choices. Exact display dimensions and whether images or worktrees were enabled for a particular user are unverified.

No images, logos, marks, mascots, proprietary fonts, or product icons are included. The label and sources disclosure are museum-authored and bilingual. The small text controls are deliberately readable substitutes for the product's icons, so their dimensions and visual weight are not exact.
