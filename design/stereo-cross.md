# 立体十字で答える（2026-11-16、第1版）

構想（ユーザーの説明）: 立体十字はデータ形式。端に足された問いで各ノードのエネルギー比率が変わり、
中心への経路が変わることで推論する。軸に読む順で語句を貼る。複数の断面から中心へ向かい、
結果が一致したら探索終了。中心から断面へつなげた軸の言葉で文を作る。マトリョーシカで層を重ね、
第1層の答えを次の層へ流す（最初の問いを付けるかが焦点）。

## この版でしたこと

| 構想 | 実装（`web/js/cross/stereo.js`、設計は `web/js/cross/design.json`） |
|---|---|
| 自然言語のまま載せるノード、6本の腕 | 中心＝モデル1つ。腕（何者か／由来／時間／能力／使い方／性格）の上に、端（問いの言葉）→中心の順で語句のノード |
| 端に当たる問いのエネルギー | 問いを2文字ずつ（英語は語）に分け、端の言葉との重なりをエネルギーにする。中心へ流れる途中で減衰、切れた鎖は届かない |
| 複数の断面の合意 | 「誰について」（名前・あなた）と「何について」（鎖）が同じ中心に閾値以上届いたときだけ答える。一つの言葉は一つの断面にだけ流れる |
| 並び替え | 候補の中心×候補の鎖を入れ替えて、最も安定した（弱い方の断面が最も強い）組を選ぶ。経過は `layers[].trace` |
| 軸の言葉をつなぐ文 | 中心の語（私は／〜は）＋経路の語句を読む順につなぐ。言語モデルなし |
| 両方から攻める | 同じ中心で、別の言葉に支えられた別の鎖がほぼ同じ強さなら両方を言う |
| マトリョーシカ | 前身・後継の鎖で別の中心につながったら、第1層の文（＋最初の問い）を第2層の問いにして付け足す |
| 型付きの不明 | 経路が途中で切れたら「〜は記録では確認できません」と、どの腕で切れたかを言う。合意しなければ何も言わない |

`closure.js` の `answer()` は、立体十字が合意したときだけその文を返し、合意しなければ従来の処理へ進む。

閾値（0.45 と 0.6）は既存の質問だけで選び（0.6）、言い換えの29問は動かす前に書いた未調整の組として使った。

2段の問い（マトリョーシカ）: 「前のモデルはいつ公開された？」に、最初の問いを付けると
「私の前のモデルはClaude Opus 4.6です。Claude Opus 4.6は2026-02-04に公開されました。」。
付けないと第2層は付け足しを見つけず、第1層の文だけになる。4問中3問で付け足しが成立
（残る1問は後継の記録が名前ではなく英文で、次の中心が見つからない）。

## 正直に分けること

- **経路なしの版（`useEnergy:false`）と立体十字は、上の2組で同じ点数だった。** この大きさの設計では、
  減衰・切断・合意の仕組みが答えの正誤を変える場面が質問票になかった。差が出たのは
  マトリョーシカ（経路なしの版では付け足しができない）と、両方から攻める答えの2つだけ。
- 言い換えで点が上がったのは、問いの言葉を2文字ずつ重ねる当て方が正規表現の意図判定より言い換えに強いため。
  十字の形そのものの効果とは言えない。
- 速さ（0.6 ms）は小さな索引の効果。
- 既存の想定問答（persona cards）がある問いは、そちらを先に使う。G3 のテストに合わせ、端の言葉に「いつまで使える」を1つ足した（言い換えの組には使っていない）。
- 端の言葉（cues）が足りない言い換え（「1回で何トークンまで返せる？」など）は答えられない。
  ここが AI 記者に毎日育ててもらう部分（ノード設計の更新）。

## 次

1. AI 記者の CI に「ノード設計の追加案」を書く仕事を足す（答えではなく cues・語句・粒度）。
2. 層を増やす（比較・時代の流れ）。比較は二つの中心へ同じ腕で同時に流す形で作れる。
3. 経路の効果を測れる質問票（似た言葉が複数の腕に当たる問い）を作り、経路なしの版と差が出るか確かめる。
