# Vera の静的回答を調べる

これは回答精度を測るための固定60問です。Vera 本体は変更しません。
期待値の出典は `questions.json` の各質問にあります。出典を確認した日は
2026-11-15（日本時間）です。実行時にはネット接続も外部AIも使いません。
出典の文章、画像、ロゴ、配布ファイルは保存していません。

## 実行

プロジェクトのルートで、実行が許可された環境から次を実行します。

```sh
node --test eval/vera/scoring.test.js
node eval/vera/run.js
```

Node 20 以降の標準機能だけを使います。成功時は60問の集計を標準出力に出し、
このフォルダーの `report.json` と `report.md` を置き換えます。
回答の誤りがあっても終了コードは0です。読込失敗、質問票の不備、回答処理の例外、
入力ファイルの実行中の変更は終了コード1です。実行できなかった場合は成績を
作らず、未実行または実行失敗として保存します。

## 画面と同じ経路

`run.js` は `web/js/closure.js` の `answer` を直接 import します。
`lib/vera.js` や複製した回答関数で代用しません。`web/js/app.js` の読込処理に合わせて
`closed` の仕様・状態を変換し、空の履歴・保存設定なしで画面を開いたときの
道具、版、モデルを選びます。各質問の直前に利用者の発言を履歴に入れます。
質問ごとに新しい会話を使い、質問に書いたモデルを選択中モデルへ自動切替しません。
画面の描画・文字送り・ブラウザーの保存設定は対象外です。

`app.js` は画面描画の副作用があるため import しません。その準備部分だけを
評価用に移し、元の該当部分と入力ファイルのSHA-256を報告書に保存します。
画面の準備処理が変わった場合はレビュアーがこの対応を再確認してください。

## 採点規則（版2）

次の4つを別々に報告します。出典がないことや、質問されていない項目の誤りで、
質問された事実の点を落としません。版1の14/60は出典などを一緒に採点した値なので、
版2と同じ指標ではありません。

1. **事実**（`fact_score`）: 質問された対象・項目の値がすべて本文にあれば `correct`。
   長文の途中に正しい値があっても加点します。同じ対象・項目で異なる値も述べたら
   `wrong`。例えば紹介文で200k、仕様で100,000と述べる回答は誤答です。
   値の不足、比較の片側の欠落、候補を選ぶ質問で選択を示さない場合も誤答です。
   保留すべき質問は `not-applicable` とし、保留の集計に入れます。
2. **出典表示**（`citation_score`）: 質問された全項目にURLがあれば `complete`、
   一部だけなら `partial`、なければ `missing`。本文のURLに加え、画面の「使った記録」で
   各事実に表示される先頭3リンクを数えます。非表示の `facts` にだけある値やリンクは
   数えません。値が間違っていても、その値の出典表示は独立して数えます。
   さらに `citation_verified_score` で、表示URLが質問票で確認した出典URLと一致するかを
   同じ3区分で報告します。単にURLがあるだけでは、そのページの内容が回答を裏付けるとは
   言えません。保留すべき質問は両方とも `not-applicable` です。
3. **回答保留**（`decline_score`）: 不明・未記録を明示して全面的に回答を保留した場合は、
   `should_decline` に応じて `declined-correctly` または `declined-wrongly`。
   保留すべきなのに断定や別の質問への回答を返したら `failed-to-decline`、
   通常の回答は `not-needed`。`closed: true` は保留を意味しません。
   無回答や壊れた事実の一覧、別モデルの紹介、長い回答の一部だけの「不明」は、
   適切な全面保留に数えません。
4. **記録にない断定**（`invented`）: 読み取った日付・数値・組織・公開形態などが、
   対応する入力レコードにも、公開元で確認した期待値にもなければ検出します。
   入力が誤っていて回答がその値を使った場合は、事実の誤答として扱い、記録にない断定には
   数えません。確認済みの正しい値を回答した場合も、入力にないという理由では数えません。
   未解析の自由文は `unverified` に残し、作り話だと断定しません。

`score` と `counts` は事実・保留の4区分です。`correct`、`wrong`、
`declined-correctly`、`declined-wrongly` の合計は60になります。
作り話は重なるため版1の排他的な `invented` 区分から外し、`summary.inventions` に
回答数と検出した断定数を出します。全件保留しても事実の正答は0です。

## 値の読み取り

表示された `facts` の既知の形式と、本文の既知の日本語表現を読み取ります。
`facts` がない本文も対象です。紹介文の `200kコンテキスト`、ラベル付きの値、
モデル名付きの比較や公開日を拾います。`facts` の外に追加した矛盾も照合します。
本文の未知の部分があっても、必要な値が読み取れて矛盾がなければ事実は正答です。
必要な値自体を読み取れなければ、事実は不足扱いです。

数値は桁区切りを無視し、`K` は1,000として扱います。元の出典が128kとだけ書く場合は
その精度で期待値を置きます（[Metaのモデル説明](https://huggingface.co/meta-llama/Llama-3.1-405B-Instruct)）。
日付はISO形式と年月日形式を認めます。質問文の引用、URL中の数字、別モデルの同じ数値は
正解の根拠にしません。比較はモデルごとに照合します。Azureと明記された終了日は、
別サービスの終了日として扱います。質問されていない項目の確認済み期待値との食い違いは
`additional_contradictions` に残します。

URL照合では末尾のスラッシュ、パラメーター、ページ内の位置指定を無視し、既知の
OpenAI・Anthropicの文書移転先、Anthropicの `www` の有無を同じものとして扱います。
それ以外のURLは、同じページだと確認できていなければ一致にしません。
URLの一致はページ内容を再確認したという意味ではありません。

## データの誤り

`report.md` の **データの誤り** と `report.json` の `data_errors` に、誤答の値を
入力JSONまで追跡して載せます。レコードID、項目、誤った値、正しい値、公開元のURL、
JSONの場所、影響した質問をすべて記録します。同じ誤りが複数の回答に現れた場合は
質問IDをまとめます。値がnullのケースは「値の欠落」に分けます。データは変更しません。

範囲は、この60問で質問した項目のうち実際の誤答に現れた値です。別項目の数値や
回答に現れなかった入力データまで正しいと保証する監査ではありません。
推薦の問題は、誤った値や欠落に加えて、候補を選んでいないという不足が重なることもあります。

## 限界と確認状況

自由文の意味や否定を完全に理解する採点器ではありません。未知の表現の矛盾や作り話は
検出できない場合があります。`invented` が0でも「作り話をしない」とは言えません。
未解析部分を正しいと認めた値でもありません。全回答の文章を人が読むために保存します。

実行中はネット接続を止めます。公開元を読んで固定した期待値を使い、回答のURLが
今も開けるか、そのページが全主張を裏付けるかは再確認しません。本物のAPI、
実行速度、個別契約・申請権限、おすすめの主観的品質も未検証（unverified）です。
重みの公開を、条件なしの再配布の許諾と同じ意味には扱いません。

架空の名前は、世界に存在しないと証明したものではなく手元に未収録の名前です。
入力に同名が追加されたら質問票の前提不成立として実行を止めます。
入力ファイルが実行中に変わった場合も、途中の結果を成績として使いません。

集計は全60問に対する事実の正答、回答可能48問での事実の正答、出典表示、
確認済みURLとの一致、回答保留の成功、記録にない断定を分けます。少数の手作り問題なので、
一般利用での精度や安全性を推定する統計調査ではありません。
